# 불침번 (Bulchimbeon)

> **당신이 자는 동안, 협업은 계속됩니다.**

시차가 큰 글로벌 팀을 위한 **비동기 Q&A 협업 서비스**입니다.
담당자가 자리에 없어도, 프로젝트 문서와 이미 승인된 지식을 근거로 AI가 대신 답합니다.

이 저장소는 불침번을 이루는 **서비스들을 한데 모아 배포하는 곳**입니다.
실제 코드는 서브모듈로 연결된 백엔드·프론트엔드 저장소에 있습니다.

---

## 어떤 문제를 푸나요

한국 팀과 영어권 팀이 함께 일할 때, 질문 하나에 답을 받기까지 하루가 걸립니다.
되물음이 한 번 더 오가면 이틀이 됩니다. 이른바 **24시간 핑퐁**입니다.

**질문하는 쪽**은 답을 기다리는 동안 작업이 막히거나, 추측으로 진행했다가 나중에 다시 작업합니다.
영어 문서가 있어도 확신이 서지 않아 결국 또 물어보게 됩니다.

**답하는 쪽**은 비슷한 질문에 매번 응답해야 하고, 퇴근 후에도 노트북을 놓기 어렵습니다.

여기서 출발한 관찰이 하나 있습니다.
**시차 때문에 막히는 질문의 상당수는 답이 이미 어딘가에 있습니다.** 문서 안에, 혹은 지난 대화 속에요.
사람이 자는 건 어쩔 수 없지만, 협업까지 멈출 필요는 없습니다.

## 어떻게 동작하나요

### 1. 확신이 없으면 지어내지 않아요

모든 답변에 **매칭률**(근거가 얼마나 충족되는지, 0~100)을 계산해서 세 갈래로 나눕니다.

| 등급 | 의미 |
|---|---|
| 🟢 **즉답** | 근거가 충분해요. 인용과 함께 바로 답합니다 |
| 🟡 **확인 대기** | 답은 있지만 확신이 부족해요. 담당자 확인을 거칩니다 |
| 🔴 **보류** | 근거가 없거나 서로 충돌해요. 사람에게 넘깁니다 |

근거가 없으면 그럴듯한 말을 만들어내는 대신, **모른다고 말하고 사람에게 넘깁니다.**

### 2. 참고자료로 시작해서, 사람이 확정해요

AI가 내놓은 답은 전부 "근거가 딸린 참고자료"일 뿐입니다.
담당자가 승인하거나 수정해야 비로소 **확정된 답**이 됩니다.
질문한 사람도 ✅ 맞았다 / ❌ 달랐다로 검증에 참여합니다.

### 3. 한국어로 묻고, 영어로 전달해요

질문자는 한국어로 편하게 묻고, 담당자에게 넘어갈 때는 영어로 번역됩니다.
이때 그냥 옮기는 게 아니라 **배경 → 질문 → 선택지** 순으로 정리해서 전달하기 때문에,
담당자는 맥락을 다시 찾아보지 않고도 빠르게 판단할 수 있습니다.

### 4. 한 번 확정된 답은 다시 기다리지 않아요

확정된 답변은 공식 Q&A로 정리되어 다음에 재사용됩니다.
같은 질문에 두 번 다시 24시간이 걸리지 않습니다.
담당자가 고친 내용에서는 교훈을 뽑아내 이후 답변 품질에 반영합니다.

## 저장소 구성

불침번은 세 개의 저장소로 나뉘어 있어요.

| 저장소 | 역할 |
|---|---|
| [`bulchimbeon-backend`](https://github.com/LetsMakeTrouble/bulchimbeon-backend) | FastAPI API 서버. 검색·답변 파이프라인, 데이터 모델 |
| [`bulchimbeon-frontend`](https://github.com/LetsMakeTrouble/bulchimbeon-frontend) | React 웹 화면. 질문·확인 카드 큐·문서함 |
| **`bulchimbeon-infra`** (여기) | 위 둘을 묶어 함께 띄우는 배포 설정 |

앞의 둘은 이 저장소에 **서브모듈**로 연결되어 있습니다.
각 서비스는 자기 저장소에서 독립적으로 개발하고, 이곳에서는 **어떤 버전끼리 묶어 배포할지**를 관리합니다.

## 시작하기

### 클론

서브모듈이 있으므로 `--recurse-submodules` 를 꼭 붙여주세요.

```bash
git clone --recurse-submodules https://github.com/LetsMakeTrouble/bulchimbeon-infra.git
cd bulchimbeon-infra
```

이미 `--recurse-submodules` 없이 받으셨다면 아래로 채울 수 있어요.

```bash
git submodule update --init --recursive
```

### 서브모듈 최신화

각 서비스 저장소에 새 커밋이 올라왔을 때, 이곳의 포인터를 옮겨주면 됩니다.

```bash
git submodule update --remote          # 서브모듈을 최신 커밋으로 이동
git add bulchimbeon-backend bulchimbeon-frontend
git commit -m "chore: 서브모듈 최신화"
```

서브모듈은 **특정 커밋을 가리키는 포인터**입니다.
따라서 이 저장소의 커밋 하나가 "프론트 A 버전 + 백엔드 B 버전" 조합을 그대로 기록합니다.
배포 후 문제가 생기면 이 저장소의 커밋만 되돌려도 양쪽이 함께 이전 상태로 돌아갑니다.
